# 星魔 / StarDevil

独立品牌前台与 API 门面原型。当前运行于本地演示模式：聊天会使用模拟流式回复、会话和 API Key 保存到 `data/xingmo.db`。生产时保留当前对外契约，将服务端上游替换为内部 NewAPI 即可。

## 已完成的第一轮能力

- 对外聊天页：星魔品牌、流式回复、新建会话、历史会话持久化。
- 星魔控制台：运营概览、API Key 创建、对话记录、内部网关配置。
- 开发者页：OpenAI Chat Completions 兼容接口示例。
- API 门面：`/v1/models`、`/v1/chat/completions`；对外模型名称固定为 `xingmo-chat`。
- API 门面使用 Bearer Key 校验；密钥仅在创建时显示明文，数据库只保存哈希。
- NewAPI 已原样克隆在 `new-api/`，不修改其源码或后台界面。

## 用户体系与模型通道（本轮新增）

- **访客与注册体系**：访客打开 `/chat` 即可直接聊天，无需注册；每台浏览器可体验 **100 条消息**，聊天不会保存，也不开放控制台、API 等完整功能。注册并登录后，聊天功能**永久免费、无限次数使用**，并可保存和查看个人对话历史。注册的新账号拥有**独立的模型通道配置**，互不干扰（每个用户一份，新用户默认继承全局默认通道）。
- **API Key 归属用户**：密钥在创建时**绑定当前登录用户**；合作方用 Key 调用 `/v1/*` 时，自动使用该 Key 所属用户的模型通道。
- **获取模型列表**：
  - 控制台「模型通道配置」页的「测试连接并列出模型」按钮直接拉取**表单当前填写的通道**（API Key 留空则沿用已保存的那把），填完即可测，不必先保存；演示模式、字段缺失或 Key 无效时返回精确原因提示。
  - 对外 `/v1/models` 支持「可选暴露真实模型名」：在通道配置中开启后返回上游真实模型列表，关闭（默认）则仍只返回统一别名 `xingmo-chat`。
- 全局默认演示账号：`admin / admin123`（仅本地演示，生产部署请修改或删除）。

## 生产接入顺序

1. 在 NewAPI 内部后台创建客户本地 7B 模型通道。
2. 在星魔控制台保存 NewAPI 内网地址、服务 Token、真实上游模型 ID。
3. 在星魔控制台保存 NewAPI 内网地址、服务 Token、真实上游模型 ID 后切换到真实转发；服务端已保留 `xingmo-chat` 的请求与响应字段映射。
4. 使用 `infra/nginx/xingmo.conf.example` 暴露星魔域名，禁止公网直连 NewAPI。
5. 将 PostgreSQL、Redis 密码和 NewAPI 所需密钥迁移到部署服务器的私有 `.env` 文件。

## 尚需客户提供的信息

- 本地模型的 OpenAI 兼容 Base URL；
- 模型真实 ID；
- 是否需要模型接口 Key；
- 是否支持 SSE 流式输出；
- 最终公网域名与 HTTPS 证书方案。
